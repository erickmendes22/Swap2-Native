# Per-game Android touch layouts

Implemented on 2026-11-05. Java/resources compilation and automated layout tests pass; device gameplay validation remains pending. This document describes the Android launcher, replacing the old concept's reference to `runtime/ui/touch_controls.mm` (not present in this tree).

## Selection and storage

`TouchProfile.java` resolves the base title ID. Automatic selects Bananza for `040074A01BF12000`, Racing for Mario Kart World (`0400C3F00006E000`), and Zelda for `0400486024DEC000`; other titles use Classic. Each game's settings page and the in-game controls panel offer the available profiles through `TouchProfile.choices`. Classic remains selectable, including menus and alternative in-game bindings. Portrait uses the classic placement.

The existing `touch_controls` preferences now store opacity, size, vibration and visibility with `@<title ID>` suffixes. Layout edits and picture position use `v1/<title ID>/<profile>/<screen shape>`; changing one game or preset does not overwrite another. Existing global preferences are read as initial defaults, and existing classic positions are retained as initial defaults. New writes are scoped to the game.

To add a game, add a profile definition and title-ID routing in `TouchProfile`, then expose the preset in both settings selectors. Keep semantic action names stable. Bump the layout namespace version if editor group semantics change. Do not infer gameplay state or automate presses from timers.

## Bananza

The approved atlas is bundled unchanged as `drawable-nodpi/s2_bananza_controls.png`. Runtime crops use measured circle centres, with button labels and pressed feedback drawn separately. The layout has two visible analog sticks and all sixteen controller bits, including stick clicks:

| Input | Purpose |
|---|---|
| Left / right stick | Movement / camera |
| Y / A / X / B | Punch / jump / punch up / punch down |
| ZR / ZL | Grab and throw / roll and fragment surf |
| R / L | Sonar clap / music |
| L+R | Bananza shortcut, held as a simultaneous chord |
| D-pad | Forms, skills and photo; game resolves context |
| Minus / plus | Map / game pause |
| L3 / R3 | Full-controller compatibility |

Auxiliary directions are available on the visible D-pad in this initial implementation, rather than a separate extras drawer. The existing app-panel handle or long press on the controls visibility button opens app settings; this does not press Plus. Camera uses the visible right stick, not an invisible full-screen drag area. The one-player default mapping follows the approved concept; co-op and user-remapped game bindings are not detected.

Placement respects system-bar/cutout insets. Default target diameters are at least 48 dp. Requested size is reduced to fit without overlapping default circles, within the supported landscape sizes tested. Custom group edits are user-controlled and can overlap; their bounds are kept inside the safe area. The centre remains available for gameplay.

The existing native input mapper owns pointer IDs, preserves hold/release and ORs button states across controls. No host production change is needed. Opening the app panel cancels inputs and suspends forwarding; profile changes, gamepad connection, focus loss, detachment and Activity pause release touches. Layout replacement also releases the previous native layout.

## Validation and handoff

### Zelda: Ocarina of Time

**Superseded on 2026-11-06 by the [Zelda 40th anniversary skin](#zelda-40th-anniversary-skin)**, which is now the profile's art; the control IDs, bits and stored settings below are unchanged. The first artwork, described here, is kept bundled, and its stored symbol choices are kept but no longer drawn or offered.

The `zelda-oot` profile bundles the approved unchanged RGBA atlas as `drawable-nodpi/s2_zelda_controls.png`. Crop centres measured from the image are X `{180,476,774,1071}` and Y `{176,475,776,1075}`, with 147px half extents. Controller labels remain visible; sticks use forest-green bases and gold outlines. All sixteen controller bits and both sticks remain available, with no game-specific input macros.

The initial **art associations are provisional**, not verified remake bindings: B/sword, A/action-roll, X/bow, Y/equipment, ZR/shield, ZL/target, R/ocarina, L/fairy, Minus/map, Plus/pause. The profile sends the named controller button exactly, regardless of its symbol. It does not equip or detect items. In the in-game panel, **Choose button symbols** selects a button, then an icon or **Letter only**. This lets players match their equipped items and actual bindings without changing the input ABI. Restore resets only these symbols, preserving layout edits and other games. The app-settings gear is excluded from game-button choices to avoid confusing game input with the application menu.

Artwork choices are persisted by stable action ID (`zelda_icon_<action>@<title ID>`); layout edits use the existing per-game/profile/screen namespace. Classic remains available. The current game note records that gameplay controls have not yet been validated; confirm the provisional symbols in the game before treating them as action labels. No phone installation was performed for this UI change.

Automated checks include Zelda routing and the Classic override, unique action IDs, all controller bits and both sticks, atlas index bounds, and geometry alongside DK and Mario Kart at all tested safe areas/scales. Validate on device: actual sword/shield/target bindings, item assignments, analog movement/camera, simultaneous holds, menu navigation, icon changes/restoration, focus loss and reopening the game.

### Mario Kart World

The racing preset provides left-stick steering (including vertical aiming), right-stick camera, A acceleration, B brake/reverse, two independent R surfaces for drift and jump, L item, X rear view, Y map, Down rewind, Plus and Minus. Holding and releasing either R surface preserves the other finger's R. These are contextual game inputs, not timed macros. Additional menu/photo/controller inputs remain available through Classic. No automatic race/menu detection is implemented in this Android frontend.

The racing profile uses the original generated artwork, recovered as `assets/artwork/swap2-native/racing/racing-touch-buttons-v1.png` and bundled unchanged in `drawable-nodpi/s2_racing_controls.png`: wheel, gas, brake, drift, item, rear view and pause. Runtime crops preserve pedal proportions; the wheel rotates with the left stick. Jump and map now use the matching approved navy/gold action atlas; Minus and the camera ring/thumb use the original controller sheet (`s2_controller_controls.png`). Rewind uses the racing sheet's back arrow. Every racing action now has artwork rather than a text-circle fallback. Hitboxes and the hide-accelerator option are unchanged. Bananza uses its separate original atlas. Resource decoding logs the selected profile and success for device diagnosis; Classic intentionally uses controller letters.

Encoding correction: both English and Portuguese string resources contained Windows-1252 bytes despite their XML UTF-8 declarations. They are now normalized to valid UTF-8, and Java compilation explicitly selects UTF-8. The touch test runner checks string resources with strict UTF-8 decoding and XML parsing.

Both settings screens expose **Auto-accelerate is enabled in the game**, off by default. This removes the A pedal from drawing **and the native hitbox list**, while leaving brake and every other control. Enable the game's own Auto-Accelerate first; the launcher neither changes this game setting nor holds A. This is deliberately different from the older runtime described in `SWAP2-NATIVE.md`, which had an armed A macro and race-HUD detection absent from this Android tree. [Nintendo's settings instructions](https://www.nintendo.com/au/support/articles/how-to-change-in-game-control-settings-mario-kart-world/) describe the in-game option. Manual and automatic racing layouts keep separate edit namespaces (`racing` / `racing-auto`); the option is scoped to Mario Kart's title ID.

Tests additionally cover racing title routing, pedal removal, preservation of brake, both R surfaces, and both layouts on the same six safe areas and three size settings. On-device checks still required: steer + accelerate + drift + item, brake while turning, charge/release jump, hold item while aiming, rear view, rewind in a supported mode, enable in-game auto-accelerate then hide the pedal, and switch to Classic for menus.

- `python dm/tools/tests/test_android_touch_profile.py`: routing, game/preset isolation, all sixteen bits, both sticks, native control limit, geometry at 60/100/150 percent on six landscape safe areas.
- `dm/host/tests/t_android_input.c`: existing routing/cancellation tests plus overlapping L and L+R owners released in either order.
- UI compilation: `gradlew.bat :compileDebugJavaWithJavac -PnxPackEngine=fake --offline`. This validates Java and Android resources; it is not a release or device APK and does not validate the production packer.
- Before shipping, Claude should build the real APK with the production pack stage and validate on the phone: move + camera + ZR + A/Y simultaneously; L with L+R; release/cancel; open/close panel; switch presets; reconnect a physical controller; rotate and restart; compare atlas crops and HUD visibility with the approved concept. No device install was performed for this change.

## Standard skin v2 (Classic)

The user approved a new graphite/cyan/coral standard controller design; the [implementation handoff](SWAP2-NATIVE-STANDARD-TOUCH-v2.md) has the artwork, measured sprite rectangles, reference placement, input mapping and acceptance checks. **Implemented on 2026-11-06** in the launcher's Classic profile: Java compilation and automated checks pass; no APK was built and no device validation has been done.

- **Artwork.** The selected clean atlas is bundled unchanged as `drawable-nodpi/s2_standard_controls_v2.png` (the draft atlas is not bundled). `TouchControls` decodes it once (`inScaled = false`) when Classic is first laid out. `TouchProfile.SPRITE_IDS` (shared by both skins) / `STANDARD_SPRITE_RECTS` copy `sprites-v2.json` (right/bottom exclusive). Sprites are looked up by semantic ID (`standardSprite`), or from a control's single guest bit (`standardSpriteFor`). They are drawn with `drawBitmap(src, dst)`, centred and aspect-preserving, with no tile behind them. Only Classic (selected explicitly, or the automatic choice for titles without their own preset) uses this atlas. Bananza and Racing keep their own art; Zelda draws the [anniversary skin](#zelda-40th-anniversary-skin) through the same renderer.
- **Landscape geometry.** `TouchProfile.placeStandard` places `layout-reference-v2.json` in the safe rectangle: the view minus system bars and display cutout, independent of the letterboxed picture. The unit is `safeHeight / 822 * size`. Left/right/centre anchors follow the handoff. Elements in the upper half of the reference keep their distance from the top, and the lower half keeps its distance from the bottom. This matches the reference exactly at 100 % and keeps the D-pad and right stick near the thumbs at other sizes. The unit shrinks, never anisotropically, until no element overlaps or leaves the safe rectangle. Because the reference fills the height, sizes above about 103 % are capped on phones. Button touch circles are at least 22 dp in radius (a 44 dp target) where neighbours leave room, and never smaller than the artwork. The host picks the nearest control when circles overlap. Pressed feedback scales only the artwork, never the hit circle.
- **Input.** There are 15 host controls and the 16 existing bits plus both sticks; no new bits. ZL, L and Minus (bits 8, 6, 11), and ZR, R and Plus (bits 9, 7, 10), are shoulder-row buttons. Each stick is one `NXT_STICK`: its base is fixed, and its cap moves by the host's stick vector up to 26/110 (left) or 22/93 (right) of the base half extent, which is 26 or 22 reference pixels at 100 %. The cap re-centres on release or cancel. L3 and R3 are independent buttons beside their sticks. The D-pad is **one** `NXT_DPAD` region, drawn as four direction sprites in a diamond. The host's 8-way resolution (`dpad_dir`) keeps diagonals, and each lit sprite follows its own bit. Face order is X top, Y left, A right, B bottom. Capture, Home and C are not placed: they have sprites but no guest bits.
- **App controls.** The visibility sprite replaces the procedural show/hide glyph. While the controls are hidden it is drawn faint and struck through. A long press still opens the controls panel. The gear sprite (bottom centre in landscape, beside the show/hide button in portrait or in a customized old layout) opens the same in-game controls panel (`openSettings`). The launcher keeps the gear's pointer and never sends it to the host. Both utilities take a pointer only on its down event, so they never steal a held stick or button. The gear is hidden while the controls are hidden (gamepad connected, or hidden by the user).
- **States.** Idle uses the user's opacity. A fresh install starts Classic at 65 %, and Reset sets 65 % for Classic. A held control is drawn at up to 1.03x, with opacity raised by up to 25 % (capped at 100 %) and a 28 % tint of its own silhouette: cyan on the left half, coral on the right, white in the centre. Release fades over 110 ms. When the system disables animations (`ValueAnimator.areAnimatorsEnabled()`), scaling and fades are off. Haptics use the existing preference.
- **Edits.** Standard layout edits use `v2/<title ID>/classic-standard/<screen>`. If the user had moved or resized a group of the old Classic placement on that screen shape (`v1/<title ID>/classic/<screen>` or the older global `group<n>@<screen>`), that placement is kept, drawn with the new art, until they press **Reset** in the layout editor. Reset then switches that screen to the v2 geometry. The old keys are never deleted. The picture position carries over. Portrait keeps the old Classic placement, drawn with the new sprites.

Checks: `python dm/tools/tests/test_android_touch_profile.py` (atlas bytes equal the clean file; the Java sprite table equals `sprites-v2.json`; placements equal `layout-reference-v2.json`; JVM test: unique IDs, rects inside the 1254 px atlas, a sprite for every guest bit, all 16 bits and both sticks with no Home/C/capture, one D-pad region, Nintendo face order, stick/D-pad arrangement, a separate namespace, the reference reproduced at 1913x822, and no overlap, safe-area escape or anisotropic scaling at 60/100/150 % on eight landscape sizes including 16:9, 20:9 and 21:9). Full main + ondevice Java compiled with JDK 17 against `android-36/android.jar` with stub `R` / `BuildConfig`.

On the phone, still to do: every sprite crisp and uncropped over light and dark scenes; both caps move independently; D-pad diagonals and simultaneous holds; L3/R3; gear and long-press open the panel without game input; hide/show; gamepad attach/detach; rotate; background/resume; release/cancel with fingers down; size 60-150 % and opacity 10-100 %; layout editor drag/pinch/reset; a game with a customized old Classic layout (should stay unchanged until Reset); DK, Mario Kart and Zelda still on their own art; display cutout.


## Zelda 40th anniversary skin

The user approved the green/gold anniversary controller layout for the existing Zelda profile. The [implementation handoff](SWAP2-NATIVE-ZELDA40-TOUCH-v1.md) has the 25-sprite transparent atlas, measured rectangles, reference placement, action/bit mappings, migration guidance and acceptance checks. **Implemented on 2026-11-06** as the `zelda-oot` profile's default skin: Java compilation and automated checks pass; no APK was built and no device validation has been done.

- **One renderer, two skins.** The standard v2 path is generalized, not copied. `TouchProfile.Skin` holds what differs between skins: the atlas's real size, its measured rectangles, the landscape items and reference canvas, cap size and travel, the four D-pad sprite offsets, the pressed palette and the suggested opacity. `TouchProfile.skin(profile)` returns `STANDARD_SKIN` for Classic, `ZELDA40_SKIN` for Zelda, and none for Bananza and Racing. `TouchControls` decodes each skin's drawable once (`inScaled = false`). It checks the decoded size against the skin's: on a mismatch it logs a `[RED]` line and draws plain shapes instead of cropping wrong rectangles. Sprites, stick caps, the D-pad, the visibility sprite, the gear and the pressed feedback all go through `drawStandard` / `drawSprite`, with the current skin's rectangles and palette. Nothing is decoded, read or extracted per frame. `placeStandard` and the `standard*` helpers remain as wrappers over `STANDARD_SKIN`, so Classic is unchanged.
- **Artwork.** `zelda-40-touch-atlas-v1.png` is bundled unchanged as `drawable-nodpi/s2_zelda40_controls.png` (1263x1245). `ZELDA40_SPRITE_RECTS` copies `sprites-v1.json` (right/bottom exclusive). The sprite IDs and their order match the standard atlas (`SPRITE_IDS`), but the rectangles do not, and nothing is derived from a grid or from the Classic atlas's 1254 px. Sprites are drawn centred and aspect-preserving, with source alpha times the user's opacity and no tile behind them.
- **Routing.** Automatic and explicit Zelda on `0400486024DEC000` use the anniversary skin. Explicit Classic on Zelda uses the standard skin. Bananza, Racing and every other title are unchanged.
- **Input.** The existing Zelda control IDs and bits are kept, as listed in the handoff: `move` / `camera` (sticks 0 / 1), `face_a`, `face_b`, `slot_x`, `slot_y`, `left_click`, `right_click`, `shoulder_left`, `shoulder_right`, `trigger_left`, `trigger_right`, `plus`, `minus`, and `directions` (one 8-way `NXT_DPAD` region, bits 12..15). Each button is drawn with the sprite of its own guest bit, so the glyph is always the controller letter the game receives. Face order is X top, Y left, A right, B bottom. L3 and R3 are separate pill buttons. Capture, Home and C are not placed: they have no guest bits.
- **Landscape geometry.** `TouchProfile.placeSkin(ZELDA40_SKIN, …)` places `layout-reference-v1.json` (1912x823) in the safe rectangle. It uses the same rules as the standard skin. The unit is `safeHeight / 823 * size`. Left/right/centre anchors follow the reference. The upper half keeps its distance from the top and the lower half its distance from the bottom. The unit shrinks, never anisotropically, until nothing overlaps or leaves the safe rectangle. Button touch circles are at least 22 dp in radius where neighbours leave room, and pressed feedback scales only the art. The D-pad region is centred on the bounding box of the four measured sprite centres (183.5, 540.5), with a 127.5-unit half extent. Each direction sprite (90 units) is drawn at its own measured offset (`ZELDA40_DPAD`), so the reference is reproduced exactly at 100 %. There is no fifth centre input. Both bases are 244 units and both caps 162; a cap moves up to 28 units with the host's stick vector, stays on its base and re-centres on release or cancel.
- **App controls.** The visibility sprite (top centre) shows and hides the controls; a long press opens the panel. The gear (bottom centre) opens the in-game controls panel and sends no guest input. Both take a pointer only on its down event. The gear is hidden while the controls are hidden.
- **States.** A held control is drawn at up to 1.03x, with opacity raised by up to 25 % and a 24 % tint of its own silhouette: warm gold (`0xF0CF7A`) on both sides, ivory (`0xFFF4DC`) in the centre, never the standard skin's cyan or coral. Release fades over 110 ms. Reduced motion turns off scaling and fades. Haptics follow the saved preference. A fresh install (no opacity saved for the game) starts at 65 %; **Reset the controls** sets 65 % with a skin. A saved opacity, size, vibration, visibility or picture position is never changed.
- **Saved layouts.** Fresh anniversary defaults use `v2/<title ID>/zelda-40/<screen>`. If the user moved or resized a group of the old Zelda placement on that screen shape (`v1/<title ID>/zelda-oot/<screen>`), that placement is kept, drawn with the anniversary art, until **Reset** in the layout editor. Reset then switches that screen to the anniversary geometry. Old keys are never deleted, and the picture position carries over. Portrait keeps the supported portrait placement (as Classic), drawn with the anniversary sprites, rather than squeezing the landscape reference.
- **Old symbols.** The old `zelda_icon_<action>@<title ID>` indices address only `s2_zelda_controls.png`. They are never read for the anniversary atlas and never removed. **Choose button symbols** is no longer offered, and the panel shows `s2_zelda40_hint` (English and Portuguese) instead. The old atlas and its strings stay in the APK.

Checks: `python dm/tools/tests/test_android_touch_profile.py`. It checks that the bundled atlas equals the selected file, with a PNG header of 1263x1245; that the Java table equals `sprites-v1.json`, with every rectangle in bounds; and that every enabled item equals `layout-reference-v1.json`, with its handoff action and bit, the cap ratio and travel, the four D-pad centres and the derived region, and Capture/Home/C absent. Source checks cover the routing, the drawable choice and the absence of old icon reads or removals. Full main + ondevice Java compiled with JDK 17 against `android-36/android.jar` with stub `R` / `BuildConfig`.
